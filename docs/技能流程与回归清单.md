# 技能流程与回归清单

## 主流程

1. 左侧先选作品，再选章节。
2. `继续写` 是主对话入口。
3. 主对话默认走 `创意讨论`，直接调用 `/api/studio/brainstorm/stream`。
4. 主对话里如果选了专用技能，提交时会直接切到对应技能工作区，并把当前输入带过去。
5. `本章工作流` 处理拆场、诊断、续写。
6. `技能库` 负责专用工具、预设管理、文风库、文件与日志查看。

## 技能行为和 Agent action

- 内置技能的前端面板、mode、输入标签、提交标签、Agent action、Agent mode 和确认要求统一记录在 `SkillBehavior`。
- 后端默认行为集中在 `skill_registry.py`；初始化内置技能文件时会写入这些字段，读取旧版技能 JSON 时会补齐缺失的 `agent_action_kind / agent_action_mode / agent_requires_confirmation`。
- Planner 的技能目录上下文会展示对应 action 和确认要求，让 `续写正文` 对应 `chapter_workflow/draft`，`去 AI` 对应 `rewrite_chapter/humanize`，`一致性检查` 对应 `consistency_check`。
- 前端本地技能目录 fallback 也保留同样字段；主对话快捷按钮会把对应内置技能 ID 放进 `active_skill_ids`，后端用这些元数据修正计划动作，且不会把内置技能 ID 当作用户自定义技能 prompt 注入。

## 作品管理

- `旧稿接管`
  入口：作品列表顶部“旧稿”
  执行：`POST /api/projects/takeover/import` 创建旧稿项目；`GET /api/projects/{project_id}/takeover` 读取状态；`POST /api/projects/{project_id}/takeover/resume` 继续未完成接管
  存储：旧稿原文、拆章结果、状态和报告写入 `.gaoxia/takeover/`；章节正文写入 `chapters/`；接续位置、上一章结尾、最近章节和写作边界写入 `core_seed.txt`、`plot_structure.txt`、`character_state.txt`、`blueprint.txt`、`global_summary.txt` 与 `checkpoint.json`
  边界：旧稿接管面向正式章节正文，不替代资料导入；文件上传只支持 `.txt`，也可以直接粘贴正文；导入阶段不逐章触发模型核验；当前项目最多接管 1000 章；前端会在读取前拒绝 30MB 以上旧稿文件；导入完成后再按章做诊断、续写或一致性检查
  恢复：恢复时会保留已有非空章节正文，不用旧稿覆盖作者已改内容；已完成状态下会补齐缺失的接管报告或接续文档
  回归：backend 单测覆盖拆章、项目创建、章节写入、报告保存、接续文档、已完成状态修复、恢复时保留已改章节和章节数量上限；前端生产构建覆盖旧稿导入弹窗编译

- `项目迁移包`
  入口：工作台更多菜单“导入迁移包 / 导出迁移包”，作品菜单“导出迁移包”
  执行：`POST /api/projects/{project_id}/migration/export` 生成 `.gaoxia-project.zip`；`POST /api/projects/migration/import` 导入迁移包
  存储：导出包写入作品 `exports/`；导入后复制到当前应用工作区，更新 `project.json`，并注册到作品列表
  边界：迁移包包含完整作品目录、`.gaoxia` 状态、`.novel-history` 历史和 `knowledge.db`；同机重复导入不会覆盖原作品，会生成新的作品 ID；项目目录内的 Obsidian Vault 会随项目迁移并保留索引、同步摘要和维护草稿；项目目录外的 Obsidian Vault 原文不会复制进迁移包，打包用的 `knowledge.db` 副本会移除外部 Obsidian 索引正文，包内 `obsidian_sync.json` 只保留配置、空统计和重新同步提示，不携带外部笔记列表、摘要或预览，包内 `narrative_state.json` 会移除 Obsidian 维护建议和动作，`.gaoxia/obsidian_drafts/` 维护草稿不会进入迁移包，包内 `project_distillation.json` 会移除外部 Obsidian 蒸馏条目并标记为需要重建，Agent 线程和 `.gaoxia/runs/` workflow 状态会保留但会移除 Obsidian 资料分析 artifact、维护 artifact、相关 trace / event 摘要以及 action / subtask 摘要，可重建的 `.gaoxia/thread_context/` 索引不会进入迁移包
  回归：backend 单测覆盖完整目录导出、导入注册、同 ID 冲突导入、项目内 Obsidian Vault 原文 / 索引 / 同步摘要保留、外部 Obsidian Vault 不复制原文、项目内 Obsidian 状态保留、迁移包 `knowledge.db` 不携带外部 Obsidian 索引正文、外部 Vault 迁移包 `obsidian_sync.json` 不携带笔记列表 / 摘要 / 预览、外部 Vault 迁移包不携带 Obsidian 维护队列和维护草稿、外部 Vault 迁移包清理 `project_distillation.json` 中的 Obsidian 蒸馏条目，以及外部 Vault 迁移包清理 Agent 线程和 workflow run 中的 Obsidian 资料分析记录并跳过线程上下文索引；UI smoke 已加入导出 / 导入校验

## 章节工作流

- `章节拆场`
  入口：技能库、本章工作流
  执行：`/api/generate/chapter-workflow/stream`，`mode=scenes`
  落盘：可写入 `blueprint`
  回归：backend 单测

- `章节诊断`
  入口：技能库、本章工作流
  执行：`/api/generate/chapter-workflow/stream`，`mode=diagnose`
  落盘：默认不自动改稿，输出诊断建议
  回归：backend 单测

- `章节生成`
  入口：技能库
  执行：`/api/studio/chapter-generate/stream`
  写入：保存到当前章节正文
  容量：后端会按作品目标字数和目标章节数计算单章容量；未指定目标字数时按当前章节距离单章均值的缺口生成完整章；用户明确要求短稿或具体字数时按用户要求处理；超出单次安全长度的目标会按小节生成，模型写短时继续追加小节
  核验：默认 `standard` 模式生成 1 个候选正文并依次执行承接事实、人物口气、可读性三类审校；`deep` 模式保留 3 个候选但经模型运行调度通道执行；择优后如有返工重点会自动修订并再次审校；小节生成时每节都会审校并合并进正文
  回归：backend 单测，覆盖标准单候选、深度多候选、三类审校聚合、超长目标小节生成和章节生成入口参数

- `续写正文`
  入口：技能库、本章工作流
  执行：`/api/generate/chapter-workflow/stream`，`mode=draft`
  写入：保存到当前章节正文
  容量：默认目标较短且整书单章均值较高时，会按章节容量建议提高本次续写目标；明确输入具体字数时不改动；完整章或超长目标会按小节生成
  核验：默认保持单候选续写保护链路，先做承接冲突检查，必要时修订，再做质量审校；小节生成时改用逐节承接审校
  回归：backend 单测

- `定稿整理`
  入口：技能库
  执行：`/api/studio/chapter-finalize/stream`
  落盘：保存修订稿；可更新 `global_summary / character_state`
  回归：backend 单测

- `场景润色`
  入口：技能库
  执行：`/api/studio/chapter-polish/stream`
  落盘：保存修订稿；可更新 `global_summary / character_state`
  回归：backend 单测

- `去 AI`
  入口：技能库
  执行：`/api/studio/chapter-humanize/stream`
  落盘：保存修订稿；可更新 `global_summary / character_state`
  回归：backend 单测，包含本地评分回归、小说专用问题识别和完整章节缩水拒绝；Agent 自学习写作回归会自动跑去 AI A/B，并从真实章节生成项目样本池，输出前后评分、平均提升、通过率和蒸馏规则；Agent 自学习模型审查会抽样做去 AI 裁判，回放历史 `chapter_humanize` 输出，并把有效改法写入项目去 AI 自学习规则；章节保存、做梦完成和自学习心跳会把有风险样本交给 `humanize_review` 智能巡检，巡检受空闲窗口、样本签名和 12 小时冷却时间控制

- `批量生成`
  入口：技能库
  执行：`/api/studio/batch-generate/stream`
  写入：后端按章节顺序写入，不并行写相邻章节；每章写回后生成核验报告，核验状态、分数、Obsidian 必写 / 禁写问题或项目记忆硬规则 / 警告禁写命中触发条件时，会按 AI 写作设置自动修订并复查
  上下文：后续章节生成会读取上一章已保存尾段，用它匹配 Obsidian 笔记和连续性证据，上一章刚出现的地点、组织、道具或线索会影响下一章资料选择
  任务状态：每次批量生成会创建或读取 `batch_tasks/{task_id}.json`，记录章节 `pending / running / completed / failed`、尝试次数、错误、结果和人工评论；传入同一个 `task_id` 会跳过已完成章节，`retry_failed=true` 时重试失败章节
  回归：backend 单测，包含核验自动修订、配置项、已完成任务恢复、跳过重复生成，以及上一章尾段驱动 Obsidian 资料进入下一章上下文和证据包

- `npm run verify`
  覆盖打包脚本静态检查、后端全部单测和前端生产构建

  使用当前保存的模型配置和许可证创建临时作品，真实调用写作模型、本地 Embedding 和第二审查模型，验证章节生成、保存、章节核验和知识检索；默认只跑 1 章，避免误发起长时间或高费用调用，扩展验证可传 `--chapters 2` 或 `--skip-auto-repair`
