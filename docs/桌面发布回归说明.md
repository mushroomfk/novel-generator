# 桌面发布回归说明

这份说明针对当前仓库的桌面版交付流程。

## 目标

把下面几段验证收成一条固定流程：

1. backend 回归
2. 前端构建
3. Python sidecar 打包
4. Tauri 调试包构建
5. `.app`、`.dmg`、sidecar 产物检查
6. `.app` 调试包重签
7. sidecar 健康检查和退出检查

## 命令

```bash
npm run verify:desktop
```

这条命令会调用 [scripts/verify-desktop-release.sh](../scripts/verify-desktop-release.sh)。

## 脚本会做什么

### 1. backend 回归

执行：

```bash
npm run backend:test
```

当前应通过全部 Python 单测。

### 2. 前端构建

执行：

```bash
npm run build
```

用于确认 Vue 模板、运行时 API 和技能区界面没有编译问题。

### 3. 打包 Python sidecar

执行：

```bash
npm run backend:bundle
```

会生成 `src-tauri/binaries/novel-backend-*`。

### 4. 验证 sidecar 可用

脚本会直接拉起打包出来的 sidecar，检查：

- `GET /api/app/health`
- `POST /api/app/shutdown`

这一步不是查文件存在，而是真的把产物跑起来。

### 5. 构建 Tauri 调试包

执行：

```bash
npm run tauri -- build --debug
```

产物默认在：

- `src-tauri/target/debug/bundle/macos/稿匣.app`
- `src-tauri/target/debug/bundle/dmg/*.dmg`

### 6. 检查应用内 sidecar

脚本会继续验证：

- `.app` 本体存在
- `.app/Contents/MacOS/novel-backend` 存在且可执行
- `dmg` 产物存在
- 如果当前环境有 `codesign`，会先调用：

```bash
npm run desktop:resign
```

这一步会补齐 `Contents/Resources`，再对当前 `.app` 重新签名。

- 然后执行：

```bash
codesign --verify --deep --strict
```

### 7. 运行应用内 sidecar

最后会直接拉起 `.app` 里的 sidecar 再做一次健康检查和退出检查

## 当前覆盖范围

这条脚本覆盖 macOS 开发环境上可自动化的桌面回归。

已经覆盖：

- backend 单测
- 前端构建
- sidecar 打包
- Tauri 调试构建
- `.app`、`.dmg`、sidecar 产物检查
- `.app` 调试包重签和签名校验
- sidecar 运行级健康检查

还没覆盖：

- GUI 自动化点击回归
- macOS notarization
- Windows / Linux 实机打包验证
- 扫描版 PDF 的 OCR 导入

## 什么时候跑

建议这几种改动都跑一遍：

- 改了 `src-tauri`
- 改了 backend 启动参数
- 改了 sidecar 打包脚本
- 改了前端运行时地址或桌面启动链
- 准备出一个可交付包之前

## 临时测试分发

如果暂时没有 Apple Developer Program 账号，仓库也支持一条测试版临时分发流程。

执行：

```bash
npm run package:test:macos
```

或者从回归到打包一次做完：

```bash
npm run release:test:macos
```

脚本会把已经生成的 `dmg` 连同下面这些文件一起整理到 `dist/test-release/macos/`：

- `安装说明-先看这个.md`
- `测试反馈清单.md`
- `SHA256SUMS.txt`
- `包信息.txt`

这条流程的边界：

- 不是 notarized 包
- 需要测试用户手动放行第一次启动
- 只适合受控测试
