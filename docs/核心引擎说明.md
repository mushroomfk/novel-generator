# 核心引擎说明

本文记录当前核心引擎的六条主线：

1. `Embedding / RAG`
2. `分步架构引擎`
3. `文风 DNA 校准`
4. `章节续写候选与审校`
5. `批量生成任务队列`
6. `自我进化报告与技能维护`

这些能力都已经接进当前界面，不额外开新页面，入口都在现有的技能区和设置区。

## 1. Embedding / RAG

### 现在的结构

- 写作模型和 Embedding 模型分开配置；设置页默认按当前写作模型推导 Embedding，用户也可以打开“单独设置 Embedding”保存独立配置。
- 设置面板现在会同时保存两组配置：
  - `model`：章节生成、蓝图、架构、文风分析这些文本生成任务
  - `embedding`：知识切片的索引和查询向量
- 后端配置文件现在是统一的 `AppConfig`，内部包含 `model` 和 `embedding` 两块。
- 后端只有收到旧的单独 `ModelConfig` 保存请求时才自动推导 Embedding；收到完整 `AppConfigUpdateRequest` 时会保留传入的 `embedding`，避免覆盖用户单独填写的向量模型。

### 索引方式

- 项目创建后，后端会把这些内容纳入知识索引：
  - 架构文件
  - 章节正文
  - 用户导入的资料
- 知识库底层现在分成三层：
  - `knowledge_chunks`：原始切片
  - `knowledge_chunks_fts`：SQLite FTS 关键词检索
  - `knowledge_vectors`：二进制向量、维度和范数
- 每次重建索引时，后端会记录：
  - `source_signature`
  - `embedding_signature`
- 章节、设定文件、导入资料发生变化时，会按 `source_key` 刷新对应来源的切片和向量。
- 只有目标章节数、schema、来源签名或 Embedding 配置发生整体变化时，才会重建完整索引。
- 旧版 `vector_json` 行会在初始化知识库时迁移到二进制向量列。

### 查询方式

- `search_project_knowledge()` 现在是混合检索：
  - 先用 FTS 取候选
  - 再只对候选做语义相似度计算
  - 阿里百炼配置可额外调用 `qwen3-rerank` 官方 OpenAI 兼容端点 `/compatible-api/v1/reranks`
  - 最后合并排序
- 返回结果会带 `match_type`：
  - `keyword`
  - `semantic`
  - `hybrid`
  - `rerank`

### 目前支持

- OpenAI-compatible `/embeddings`
- 阿里百炼 `qwen3-rerank` 官方 OpenAI 兼容 `/compatible-api/v1/reranks`
- 动态配置 `base_url`、`model_name`、`dimensions`、`retrieval_k`、`batch_size`
- 技能区里直接导入资料、搜索资料，并把结果用于项目上下文
- 项目资料库和作者参考库支持 `txt / md / json / csv / html / docx / pdf` 文件导入
- `联网考据` 优先使用阿里百炼联网搜索查询历史典故和史实，博查可作为备用搜索源，结果可保存为项目资料继续参与检索

### 目前边界

- 现在还是项目内混合检索，不是独立的外部向量库服务。
- 搜索索引仍保存在项目本地 SQLite，不依赖独立外部向量库。

## 2. 分步架构引擎

### 目标

整本架构不再只是一键生成四段文本，现在可以按模块逐步生成、逐步修改、逐步写回。

### 当前步骤

技能区 `分步架构` 支持这些模块：

- `core_seed`
- `character_design`
- `world_building`
- `plot_structure`
- `character_state`
- `blueprint`
- `global_summary`

### 工作方式

- 前端先把当前项目文档同步到一个 `workspace`
- 用户选择要生成的步骤
- 后端只生成这个步骤对应的内容
- 返回：
  - `headline`
  - `summary`
  - `content`
  - `checklist`
- 前端可以只替换当前模块，也可以一次性把整个工作区写回项目

### 继续扩写

- `mode=continue` 时，分步架构会带上新增章节目标
- 写回项目时可以直接同步更新 `target_chapters`

### 使用位置

- 技能区 `分步架构`
- 后端接口：
  - `POST /api/generate/architecture/step/stream`
  - `PUT /api/projects/{project_id}/architecture/workspace`

## 3. 文风 DNA 校准

### 现在有的能力

- 样文分析
- DNA 分析
- 文风融合
- 文风校准
- 叙事校准
- 校准回滚
- 作者参考库
- 作者参考库语义检索

### 数据结构

每个文风方案现在会保存这些核心字段：

- `instruction`
- `analysis`
- `dna_analysis`
- `narrative_for_architecture`
- `narrative_for_blueprint`
- `narrative_for_chapter`
- `source_sample`
- `calibration_reference`
- `calibration_notes`
- `last_calibrated_at`
- `pre_calibration_snapshot`

### 三段式叙事约束

文风方案现在不只管“语言像不像”，还会分别约束：

- 架构阶段怎么写
- 蓝图阶段怎么写
- 正文阶段怎么写

这三段内容会直接被生成链路读取。

### 作者参考库检索

- 作者参考资料现在不只是列表展示。
- 技能区里可以直接按关键词或语义搜作者参考。
- 后端会给作者参考资料补向量，查询时做混合排序。
- 文风方案在参与章节、蓝图、架构生成时，会优先带上命中的作者参考片段。

### 校准机制

- 第一次校准前，会自动保存 `pre_calibration_snapshot`
- `校准文风` 主要收敛：
  - `instruction`
  - `analysis`
  - `dna_analysis`
- `校准叙事` 主要收敛：
  - `narrative_for_architecture`
  - `narrative_for_blueprint`
  - `narrative_for_chapter`
- 回滚时会恢复快照里的文风字段和校准备忘

### 使用位置

- 技能区 `文风与DNA`
- 后端接口：
  - `POST /api/studio/styles/analyze/stream`
  - `POST /api/studio/styles/analyze-dna/stream`
  - `POST /api/studio/styles/calibrate/stream`
  - `POST /api/studio/styles/calibrate-narrative/stream`
  - `POST /api/studio/styles/{name}/rollback-calibration`

## 4. 上下文预算与模型错误分类

### 上下文预算

- `build_project_context_bundle()` 会按任务类型计算上下文预算，返回 `budget_report`。
- 当前章节正文过长时，会保留开头和结尾，中间用说明性占位文本替代。
- 检索线索过长时，会优先压缩检索块，避免资料片段挤掉任务指令和章节上下文。
- 当前默认字符预算：
  - 架构、续写：`18000`
  - 人物视角：`16000`
  - 文风模仿：`20000`
  - 改写模式：`22000`

### 模型错误分类

- 生成链路和做梦链路现在会把模型调用异常分类后写入 `prompt_history.jsonl`。
- 已分类字段包括 `error_kind`、`error_title`、`error_user_action`、`error_retryable`。
- 当前覆盖认证、账单、限流、上下文过长、模型不存在、服务端错误、网络连接中断、超时、请求格式错误和未知错误。
- 聊天模型、Embedding、重排序、项目愿景、联网考据和 qwen-doc 文档抽取请求都会经过统一 JSON 传输层，对 SSL EOF、远端提前断开、连接重置、429 和 5xx 短时错误进行两次重试；连续失败后再返回分类后的用户提示。
- `Prompt 历史` 查询会同时匹配错误类型和错误标题，便于从日志里定位模型配置或服务状态问题。

## 5. 章节续写候选与批量任务

### 章节生成候选

技能区 `章节生成` 现在使用多候选续写流程：

- 先按 `target_words / target_chapters` 计算单章容量，把容量提示写入项目上下文
- `chapter_generate` 未指定目标字数、整书架构已齐全且单章均值达到长章节阈值时，会按当前章节距离单章均值的缺口作为完整章目标；Agent 里直接说“继续写第一章”也按这个规则处理
- 如果作品单章均值较高，而章节工作流请求仍是 1500 到 1800 字这类默认短目标，后端会把本次生成目标提高到当前章节的一段容量
- 用户明确写了短稿、片段、开头或具体字数时，后端尊重用户输入；“当前正文约 3870 字”“保存校验：当前正文约 3870 字”这类状态描述不会被当作用户字数要求
- 当目标超过单次安全长度时，后端会按不超过 5500 字规划小节；每节继承前文、独立生成和审校，再合并成完整正文。如果模型单节写短，后端会按实际正文长度继续追加小节，直到接近完整章目标或达到安全次数上限
- 先生成承接简报和场景计划
- 并行生成 3 个候选正文，分别偏向对白承压、动作压迫和段尾推进
- 每个候选都会进入三类审校：承接事实、人物口气、可读性
- 三类审校并行执行，结果按固定权重合成总分
- 主流程按通过状态、分数、严重问题数量和候选顺序择优
- 候选未通过且有返工重点时，会修订一次并重新执行三类审校

这条流程用于 `chapter_generate`。`chapter_workflow` 的 draft 模式默认仍保留单候选承接保护链路；如果用户明确要求完整章或 15000 字这类超长目标，也会进入小节生成流程。

章节改写使用另一条写回校验：`rewrite_chapter` 保存正文后会读取实际正文长度，并和用户字数要求、项目单章均值比较。重写、改写、定稿整章时，保存后的正文低于完整章容量会触发自动续写；如果剩余缺口超过 5500 字，会把完整缺口交给小节生成流程，由流程按实际正文长度继续追加小节。补足过程中任一请求失败，或最终仍未达到容量阈值，都会恢复本轮改稿前正文，避免把不合格短稿或半截扩写留在章节里。去 AI、短稿、片段、开头等明确短文本请求不会触发扩写。模型自报的“约 15000 字”“完整章节”等修改说明不会原样进入最终反馈。产物 `metadata` 会记录 `saved_word_count`、`length_target_words`、`length_status` 和 `length_completion_*`，供后续回看和自我进化报告使用。

### 批量生成任务队列

`/api/studio/batch-generate/stream` 现在按任务队列处理章节：

- 请求可以带 `task_id`，不带时后端创建一个新的任务 ID
- 任务状态保存在应用数据目录 `batch_tasks/{task_id}.json`
- 每章有独立状态：`pending / running / completed / failed`
- 任务记录保存章节编号、章节 ID、尝试次数、最后错误、单章结果和人工评论
- 再次传入同一个 `task_id` 时，已完成章节会直接返回旧结果，不重新生成
- `retry_failed=true` 时才会重试失败章节
- 章节仍然按顺序生成，不并行写相邻章节，避免破坏上下文连续性

前端批量生成面板会显示并回填任务 ID，也能提交人工评论和失败章节重试开关。

## 6. 故事总览抽取

- `StoryOverview` 会先用本地规则从人物设定、人物状态、架构文件、资料和章节里提取人物、事件、地点、组织/势力、道具和技能候选。
- 明确写在人物设定或人物状态里的名字直接保留；“慕容皝与慕容恪”这类并列人物标题会拆成独立人物。
- 从正文、资料和其他架构文本里自动发现的新名字，必须同时满足出现次数和人物语境证据，避免把历史短语、制度、地点、组织、技能或抽象概念当成人物。
- 项目已经有人物设定时，导入资料仍进入资料库和蒸馏上下文，但不会再把长篇考据报告里的概念词批量灌进人物图谱和世界要素。
- 打开架构总览时，前端会请求 `GET /api/projects/{project_id}?review_characters=true`。如果当前模型配置可用，后端会把候选名、类别和证据句交给模型复核；模型只能在候选词里选择，不允许新增人物或世界要素。
- 复核结果缓存在项目目录 `.gaoxia/story_overview_character_review.json` 和 `.gaoxia/story_overview_entity_review.json`。项目内容和模型配置没有变化时，后续打开架构总览直接使用缓存。
- 普通项目详情读取不主动调用模型；未配置模型或模型复核失败时，架构总览继续使用本地规则结果。
- 世界要素会继续抽取事件、地点、道具、技能、场景和组织/势力；事件只收真正推动情节的动作句，章节标题保留在场景里，纯环境描写不会进入事件。事件、地点、组织、道具和技能会同时经过本地规则与模型复核，过滤句子残片、泛称、比喻用法、抽象设定和章节提示词。

## 7. 自我进化报告与技能维护

技能区 `自我进化` 会把项目学习记录、Agent 轨迹、Prompt 历史和技能状态合并成一份只读报告。

### 报告来源

- 项目目录 `.gaoxia/learning/reviews.jsonl`：记忆候选、技能候选、章节低分修订经验
- 应用数据目录 `logs/agent_trajectories.jsonl`：执行计划、失败状态、章节产物 metadata
- 应用数据目录 `logs/prompt_history.jsonl`：模型调用失败、错误分类、用户处理建议
- 技能目录 `skills/` 和 `.skill_usage.json`：技能来源、使用次数、沉淀次数、更新时间

### 候选类型

- `skill`：适合沉淀成用户技能的写作流程或修订经验
- `memory`：需要作者确认后才能写进项目记忆的偏好、目标或约束
- `prompt`：适合进入提示词回归样本的执行失败或模型调用失败
- `review`：适合进入章节质量评测集的低分核验或自动修订样本

### 技能维护

`GET /api/studio/skills/curation` 会给每个技能返回 `active / stale / archive_candidate` 状态。

- 内置技能默认保留
- 用户锁定的技能保留
- 有使用记录或沉淀记录的用户技能保留
- 长时间没有使用记录的用户技能会提示复查或归档

这套机制不直接改长期记忆、提示词方案或技能文件，只提供候选、证据和建议。

## 8. 这些模块和现有界面的关系

- 设置区：
  - 新增 Embedding 配置
- 技能区：
  - `知识检索` 现在可以走语义检索
  - `联网考据` 可以把阿里百炼或博查的联网搜索结果整理成写作素材，并手动写入资料库
  - `分步架构` 现在是真正的工作区，不是占位
  - `章节生成` 会走多候选正文和三类并行审校
  - `批量生成` 会展示任务 ID，并支持失败重试和人工评论
  - `自我进化` 会展示经验候选、失败样本、章节评测样本和技能维护建议
- `文风与DNA` 现在能直接展示、保存、校准、回滚
- `文风与DNA` 里还能直接搜索作者参考库

外层布局没有改，还是现有界面。
