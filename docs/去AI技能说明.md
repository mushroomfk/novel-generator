# 去AI技能说明

这版 `去 AI` 不再只是丢一句“把模型腔去掉”给模型。

现在它分成两块：

- 一套固定的去痕规则
- 一套本地效果回归评分

规则按中文小说正文场景整理，重点处理常见模型腔、解释腔和模板化结尾。

## 现在会重点处理什么

这版优先盯这些问题：

- AI 连接词和套话，比如“此外”“值得注意的是”“某种程度上”
- 意义宣告句，比如“重要一步”“标志着”“奠定基础”
- 解释腔，比如“这意味着”“这表明”“让读者感受到”
- 口号式对照句，比如“不仅仅是……更是……”
- 总结式结尾，比如“总的来说”“未来可期”“迈出重要一步”
- 过匀的三连排比
- 助手口吻残留，比如“当然”“希望这对你有帮助”

小说场景里最重要的一条是：少讲意义，多给动作、对白、停顿和细节。

## 在界面里怎么用

1. 打开技能库
2. 进入 `去 AI`
3. 选当前章节
4. 可选填补充要求，比如“保留冷硬气质”“对白别修得太顺”
5. 点 `开始去 AI`

运行完以后，结果区会多一块本地评分：

- 原文评分
- 修订后评分
- 分数变化
- 还残留的高频问题

这个评分不是模型评分，是本地规则扫出来的回归分。它的作用是方便复盘，不是替代人工判断。

## 这版具体做了什么

- 去 AI 改稿改成独立 prompt，不再和普通改稿共用一套指令
- 在送给模型前，先扫原文里最明显的模板腔，再把这些问题塞回 prompt
- 模型返回后，本地再做一次前后对比，给出评分变化
- 如果模型没写修改说明，会用本地对比结果补一版简要说明

## 回归怎么做

后端补了固定回归样例，覆盖这些场景：

- 意义宣告和连接词
- 解释腔和总结句
- 模糊归因
- 助手口吻残留
- 三连排比

执行命令：

```bash
npm run backend:test
```

重点看这两个用例：

- `backend/tests/test_humanize_service.py`
- `backend/tests/test_studio_service.py`

## 边界

- 这是规则回归，不是“文学性自动评分”
- 分数高，不代表文风一定好，只代表常见模型腔更少
- 分数低，也不一定全错，某些句式在特定人物口吻里本来就能成立
- 现在这版主要针对章节正文，不是给说明文、公文、营销文案做的
